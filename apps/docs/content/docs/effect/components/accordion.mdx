Use an Accordion for content people can explore one section at a time, such as answers, settings, or a course outline. Each heading is a button that opens its panel.

  name="accordion/basic"

/>

## Installation

```bash
npm install @ui-sdk/effect @ui-sdk/core
```

## Composition

`Accordion` is one headless component. Its `view` gets these parts:

```text
Accordion
├── accordion.root
└── accordion.item
    └── accordion.in("item", { value })
        ├── header
        │   └── trigger
        └── panel
```

Give every item a unique `value`. `accordion.in("item", { value })` gives the header, trigger and panel of that item, which take its value from it. Put the trigger inside the header, then add the panel it opens. The accordion's value is always an array of open item values, even when only one can be open.

Apply the header to a heading at the level that fits the surrounding document. Tab moves between triggers; Enter or Space opens and closes their panels. Arrow keys, Home and End do nothing here: the APG removed them from the pattern, and a screen reader’s heading navigation already reaches each trigger.

## Usage

Call it in your view and apply its parts:

```ts
import * as Html from "@effect/ui/html/Html"
import { Accordion } from "@ui-sdk/effect/accordion"
import * as Schema from "effect/Schema"

const Example = Html.component({
  name: "Example",
  model: Schema.Null,
  message: Schema.Never,
}).make({
  init: () => null,
  update: ($) => $.model,
  view: (h) =>
    Accordion(h, {
      view: (accordion) => {
        const shipping = accordion.in("item", { value: "shipping" })
        return accordion
          .root(h.div)
          .children(
            accordion
              .item(h.div, { value: "shipping" })
              .children(
                shipping
                  .header(h.h3)
                  .children(shipping.trigger(h.button).children("Shipping")),
                shipping.panel(
                  h.div.children("Orders arrive in five to seven days.")
                )
              )
          )
      },
    }),
})

export { Example }
```

A closed panel's part returns `undefined`, so give it its children before you apply it.

## Build Your Own

`@ui-sdk/effect/accordion` comes with a ready-made Accordion. If you'd like to build your own, with your own names, start from the `accordion` primitive in `@ui-sdk/core`:

```ts title="faq.ts"
import { accordion } from "@ui-sdk/core/accordion"
import { createParts } from "@ui-sdk/effect/primitive"

const Faq = createParts(accordion, {
  name: "Faq",
  tags: {
    root: "div",
    item: "div",
    header: "h3",
    trigger: "button",
    panel: "div",
  },
  present: ["panel"],
})

export { Faq }
```

Each part keeps the behavior, state and data attributes of its ready-made counterpart. See [Rendering](../rendering) and [Custom Parts](../custom-parts) for more.

Pass `disabled` to an item or to a single trigger to prevent changes, or to the accordion to disable every item. Disabled triggers stay in the tab order so people can still discover them. A disabled `<fieldset>` around the accordion disables it too.

## Collapsible

Pass `collapsible: false` when the open item should stay open until another item replaces it. Pair it with `defaultValue: ["overview"]` so a panel starts open.

The open trigger reports `aria-disabled="true"` because pressing it leaves its panel open.

```ts
Accordion(h, {
  props: { collapsible: false, defaultValue: ["overview"] },
  view: (accordion) => items(accordion),
})
```

## Controlled

Keep `value` in your Model, pass it as a prop, and change it in `update` when `ValueChange` arrives. [State and Events](../state-and-events) covers the shared pattern.

To refuse a change, leave the Model as it is. To ask first, run a Command that asks, and change the Model when its answer arrives. Every change also brings its [reason](#reasons), and each item's own `ItemOpenChange`, with the item's value as `key`.

## Animation

Each part has a `data-slot`, such as `accordion-panel`. The panel exposes its measured height as `--accordion-panel-height`. Animate that height to or from zero with `data-starting-style` and `data-ending-style`:

```css
[data-slot="accordion-panel"] {
  height: var(--accordion-panel-height);
  overflow: hidden;
  transition: height 0.15s;

  &:is([data-starting-style], [data-ending-style]) {
    height: 0;
  }
}
```

The panel stays mounted until its exit animation finishes. An item's `ItemOpenChangeComplete` arrives afterward with the open state. A panel that starts open appears right away, with no animation and no completion event.

## URL Hash

<span id="open-the-item-in-the-url-hash" />

A hash can name an item's `value` instead of an element inside its panel. Read it from your route, or with a Subscription on `hashchange`, then open and focus the matching item through your controller, from a Command:

```ts
const OpenFromHash = Command.make(
  "OpenFromHash",
  { args: { value: Schema.String } },
  ({ value }) =>
    Effect.sync(() => {
      if (items.some((item) => item.value === value)) {
        accordion.open(value)
        accordion.focus(value)
      }
      return Component.noop
    })
)
```

Check the value against your items first. A controller can hold a value even when no item renders it.

## Query String

<span id="keep-open-items-in-the-query-string" />

Use `open` query parameters when several items should be shareable. Keep the open items in your route's search, and write accepted changes back from `update`, with your router's navigation, like `Router.patchSearch`.

## Scroll into View

<span id="scroll-an-item-into-view" />

Scroll after `ItemOpenChangeComplete`, when the panel has its full height. Scrolling on `ItemOpenChange` would measure it before it opens. The [Expand All example](#expand-all) shows the full setup with `HtmlCommand.scrollIntoView`, and scrolls only when someone opens a single item.

## Styling

Style the parts with the attributes below. This turns the chevron as its panel opens, mirrors it in right to left with `:dir(rtl)`, and dims disabled triggers:

```css
[data-slot="accordion-trigger"] {
  & > svg {
    rotate: -90deg;

    &:dir(rtl) {
      rotate: 90deg;
    }
  }

  &[data-open] > svg {
    rotate: 0deg;
  }

  &[data-disabled] {
    color: gray;
  }
}
```

### Events

Each event carries plain data, for your messages and your tests.

| Event                    | Carries                                                                       |
| ------------------------ | ----------------------------------------------------------------------------- |
| `ValueChange`            | `{ value, reason, source }`: the open items, and the [reason](#reasons)       |
| `ItemOpenChange`         | `{ value, reason, source, key }`: one item's open state, before `ValueChange` |
| `ItemOpenChangeComplete` | `{ value, key }`, after the item's panel animation                            |
