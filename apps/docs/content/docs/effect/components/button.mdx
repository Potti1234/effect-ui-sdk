---
title: Button
description: Run an action, show that it's working, and keep it reachable when disabled.

Button applies to a native `button` and adds what it doesn't do on its own: it stays pending while an async action runs, so a form can't submit twice, announces slow actions to screen readers, can stay focusable while disabled, and keeps the same behavior when it renders a link. For a plain click handler, a native `button` is enough.

## Installation

```bash
npm install @ui-sdk/effect @ui-sdk/core
```

## Composition

`Button` is one headless component. Its `view` gets one part:

```text
Button
└── button.root
```

Apply `root` to a native `<button>`, or to a link or any other element that acts as one. The part writes `type="button"` on a native button by default.

## Usage

Call it in your view, apply its part, and handle the press like any element's, with `.on("click", Message)`:

```ts
import * as UiSchema from "@effect/ui/UiSchema"
import * as Html from "@effect/ui/html/Html"
import { Button } from "@ui-sdk/effect/button"
import * as Schema from "effect/Schema"

const ExampleMessage = UiSchema.TaggedEnum({ PressedSave: {} })

const Example = Html.component({
  name: "Example",
  model: Schema.Null,
  message: ExampleMessage,
}).make({
  init: () => null,
  update: {
    PressedSave: ($) => $.run(save()),
  },
  view: (h) =>
    Button(h, {
      view: (button) =>
        button
          .root(h.button.on("click", ExampleMessage.PressedSave()))
          .children("Save"),
    }),
})

export { Example }
```

Your click handler runs before the button's own, and runs even while the button is disabled with `focusableWhenDisabled` or pending, so check those in `update` when they matter. For work the button should wait for, use `action`.

## Pending

Pass an `action` prop that returns a Promise to keep the button pending until it settles. The button runs it on each press it accepts, never while it's disabled or pending, keeps focus and ignores further presses while it waits.

```ts
Button(h, {
  props: {
    action: () => new Promise((resolve) => setTimeout(resolve, 1500)),
    pendingAnnouncement: "Saving",
  },
  view: (button) => button.root(h.button).children("Save"),
})
```

After one second, it announces "Loading" to screen readers. Set `pendingAnnouncement` to change that message, as above, or use an empty string to silence it.

`action` runs inside the button's own listener, outside `update`, so it can't send a message. Keep the work it waits for in the Promise, and read the result from the button's state.

## Pending Content

To change what the button shows while it waits, mark content with `data-show="idle"` or `data-show="pending"` and hide it in the other state with one CSS rule each, or use Tailwind's `in-data-pending` variant:

<StyleTabs>

```css
[data-slot="button"]:not([data-pending]) [data-show="pending"],
[data-slot="button"][data-pending] [data-show="idle"] {
  display: none;
}
```

```ts
button
  .root(h.button)
  .children(
    arrowIcon(h).attr("class", "in-data-pending:hidden"),
    spinnerIcon(h).attr("class", "not-in-data-pending:hidden"),
    "Save"
  )
```

</StyleTabs>

<ComponentExample
  name="button/pending-content"
  caption="Press Save. Its arrow turns into a spinner while it saves."
/>

Keep the label and change only the visual, as above. If the text has to change too, swap it the same way, without an `aria-label`. [Pending Buttons](#pending-buttons) explains why:

```ts
button
  .root(h.button)
  .children(
    h.span.attr("data-show", "idle").children("Save"),
    h.span.attr("data-show", "pending").children("Saving…")
  )
```

## Handling Errors

If `action` throws or its Promise rejects, the button's `state.error` holds the error. Use it to show a message or a retry label. The next press clears the error and runs the action again.

The demo reads `button.state` in its view to change the label.

## Changes After an Await

`action` receives the event and `{ source }`, which says how the button was pressed. If it changes another ui-sdk component after an `await`, wrap that change in `withSource` to keep the original source. Otherwise, the later change is reported as `"programmatic"`.

Here `save()` is your request and `status` is an Input's controller:

```ts
import { withSource } from "@ui-sdk/effect/observe"

Button(h, {
  props: {
    action: async (_event, { source }) => {
      await save()
      withSource(source, () => status.setValue("Saved"))
    },
  },
  view: (button) => button.root(h.button).children("Save"),
})
```

[Observe](/docs/core/observe#keep-the-source-after-an-await) explains source tracking. Preserving `"agent"` lets [`undoSource("agent")`](/docs/agents/connect-an-agent/history-and-undo#undo-the-agents-changes) include that later change.

## Disabled

Set `disabled` to prevent presses and remove the button from the tab order. A disabled `<fieldset>` around the button disables it too.

```ts
Button(h, {
  props: { disabled: true },
  view: (button) => button.root(h.button).children("Disabled"),
})
```

## Focusable When Disabled

Add `focusableWhenDisabled` when people should still be able to focus a disabled button. It uses `aria-disabled` instead of the native `disabled` attribute. Presses still do nothing: `action` doesn't run, and a click handler of yours should check the same condition in `update`.

Use `aria-describedby` to explain why the action is unavailable:

```ts
h.div.children(
  Button(h, {
    props: { disabled: true, focusableWhenDisabled: true },
    view: (button) =>
      button
        .root(h.button.attr("aria-describedby", "publish-hint"))
        .children("Publish"),
  }),
  h.p.attr("id", "publish-hint").children("Add a title to publish.")
)
```

## Links

Apply `root` to an `<a>`. It keeps its `href` and link semantics, including opening in a new tab. A disabled link cannot navigate and leaves the tab order.

```ts
Button(h, {
  view: (button) =>
    button.root(h.a.attr("href", "/docs/effect")).children("Get started"),
})
```

## Forms

Set `type: "submit"` to submit a form or `type: "reset"` to restore its default values. The default, `"button"`, does neither.

```ts
Button(h, {
  key: "submit",
  props: { type: "submit" },
  view: (button) => button.root(h.button).children("Subscribe"),
})
```

<ComponentExample
  name="button/form"
  caption="Edit the email and choose Subscribe, or press Enter in the field. The console logs each submission, and Reset restores the original email."
/>

Button tracks the Promise its own `action` returns, not the form's submit. For a submit that runs a Command, keep your own pending flag in the Model and set `disabled` on the button while it runs, with [`focusableWhenDisabled`](#focusable-when-disabled) so the button keeps focus while it waits.

## Styling

Use `data-pending` to show a spinner or waiting cursor, and `data-disabled` to style an unavailable action. The button's `data-slot` is `button`, and its attributes are listed under [Data Attributes](#data-attributes).

Button has no events of its own. A press reaches your `update` through your element's `.on("click", Message)`.

| Prop     | Receives                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| `action` | The event and `{ source }`, how the button was pressed. A returned Promise keeps it pending until it settles. |

## Accessibility

Give the button a clear text label. If it contains only an icon, add an `aria-label`. Native buttons respond to Enter and Space; links respond to Enter.

### Pending Buttons

While its action runs, the button tells assistive technology it's busy, so you don't need to add anything:

- It sets `aria-busy="true"` and `aria-disabled="true"`, and ignores presses until the action settles. It keeps focus the whole time.
- After a second, it announces `pendingAnnouncement` ("Loading" by default) through a polite live region. Quick actions stay silent. This is a status message: people hear it without focus moving.

To show progress, keep the label and change only the visual, like a spinner. Changing the text renames the button while it has focus: screen readers don't reliably announce a new name on the focused element, so the change mostly helps sighted users, and the button's width shifts as the text changes length. The announcement already tells everyone it's working.

```ts title="Do"
Button(h, {
  props: { action: save, pendingAnnouncement: "Saving" },
  view: (button) =>
    button
      .root(h.button)
      .children(
        arrowIcon(h).attr("data-show", "idle"),
        spinnerIcon(h).attr("data-show", "pending"),
        "Save"
      ),
})
```

```ts title="Don't"
Button(h, {
  props: { action: save },
  view: (button) =>
    button
      .root(h.button.attr("aria-label", "Save"))
      .children(
        model.saving ? "Saving…" : "Save",
        h.span
          .attr("aria-live", "polite")
          .children(model.saving ? "Saving" : "")
      ),
})
```

The second button tracks `saving` itself, shows text its accessible name doesn't contain, and announces the same state twice. If the text has to change anyway, swap it with `data-show` and leave out `aria-label`, so the button's name always contains the text on screen. See [Pending Content](#pending-content) for the markup.
