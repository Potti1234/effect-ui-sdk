Use radios for a short list of choices where only one can be picked, like a shipping speed or a plan. The group keeps one value and gives the whole list a single tab stop.

/>

## Installation

```bash
npm install @ui-sdk/effect @ui-sdk/core
```

## Composition

`RadioGroup` is one headless component. Its `view` gets these parts:

```text
RadioGroup
├── radioGroup.group
├── radioGroup.radio
├── radioGroup.input
└── radioGroup.in("radio", { value })
    └── indicator
```

Give each radio a `value`: `radioGroup.radio(h.button, { value })`. The `input` part, with the same `value`, is the radio's hidden native radio that takes part in forms: put it beside the button. `radioGroup.in("radio", { value })` gives the indicator of that radio, which takes its value from it. Wrap each radio with its text in a label. The group's value is the checked radio's value, and the indicator shows while its radio is checked.

## Usage

Call it in your view and apply its parts:

```ts
import * as Html from "@effect/ui/html/Html"
import { Field } from "@ui-sdk/effect/field"
import { RadioGroup } from "@ui-sdk/effect/radio"
import * as Schema from "effect/Schema"

const speeds = [
  { value: "standard", label: "Standard" },
  { value: "express", label: "Express" },
]

const Example = Html.component({
  name: "Example",
  model: Schema.Null,
  message: Schema.Never,
}).make({
  init: () => null,
  update: ($) => $.model,
  view: (h) =>
    Field(h, {
      view: (field) =>
        field.root(h.div).children(
          field.label(h.label).children("Shipping speed"),
          RadioGroup(h, {
            props: { defaultValue: "standard" },
            view: (radioGroup) =>
              field
                .control(radioGroup.group(h.div))
                .children(
                  speeds.map((speed) =>
                    h.label
                      .key(speed.value)
                      .children(
                        radioGroup
                          .radio(h.button, { value: speed.value })
                          .children(
                            radioGroup
                              .in("radio", { value: speed.value })
                              .indicator(h.span)
                          ),
                        radioGroup.input(h.input, { value: speed.value }),
                        speed.label
                      )
                  )
                ),
          })
        ),
    }),
})

export { Example }
```

Apply the field's `control` to the group, and the field's label names it. Without a field, name it with `aria-label` or `aria-labelledby`. Without `defaultValue`, nothing starts checked and Tab enters on the first enabled radio.

## Disabled

Pass `disabled` to the group, or to one radio and its input. Disabled radios can't be focused or checked, and arrow keys skip them. A disabled fieldset disables the group too, and a disabled group submits nothing.

## Controlled

Keep `value` in your Model, pass it as a prop, and change it in `update` when `ValueChange` arrives. To keep the current value, leave the Model as it is. A [controller](#controller) from `createRadioGroupController()` checks a radio from anywhere, like the Choose Team button below: call it from a Command. Create one controller per mounted group.

## Form

Each radio is a button with the `radio` role, and its `input` part a hidden native radio, so the group takes part in forms. Pass `name` to submit the checked value; the group submits nothing without a name or a checked radio. `required` blocks submission until there's a choice, and a reset returns to `defaultValue`.

Pass `form` with a form's id to join it from elsewhere on the page, as this group does.

## Animation

The indicator has `data-starting-style` as it appears and `data-ending-style` while it leaves, and stays mounted until its exit finishes. Transition from those states:

```css
[data-slot="radio-indicator"] {
  transition:
    opacity 0.15s,
    scale 0.15s;

  &:is([data-starting-style], [data-ending-style]) {
    opacity: 0;
    scale: 0.5;
  }
}
```

`keepMounted` keeps the indicator in the page while unchecked, with `data-unchecked`. Here it lets a hovered option preview its dot.

## Loop

Arrow keys wrap from the last radio to the first. Pass `loop: false` to stop at the ends.

```ts
RadioGroup(h, {
  props: { defaultValue: "low", loop: false },
  view: (radioGroup) => options(radioGroup),
})
```

Use `data-checked` and `data-unchecked` for the checked state, and `data-disabled`, `data-readonly` and `data-required` for the rest. The indicator gets the same state attributes as its radio, and the group gets `data-disabled`, `data-readonly` and `data-required`.

## Accessibility

Radio groups follow the [WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/), and behave like native radios that share a name. The `radio` part gives its button the `radio` role, and the `input` part is a hidden native radio that takes part in forms.

### Keyboard

| Key        | Does                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| Tab        | Moves into the group, onto the checked radio or the first enabled one   |
| Arrow keys | Move to the next or previous radio and check it, skipping disabled ones |
| Space      | Checks the focused radio                                                |
| Enter      | Submits its form                                                        |
