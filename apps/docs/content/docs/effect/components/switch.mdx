Use a switch for a setting that takes effect as soon as it changes, like Airplane mode or a notification preference. Keep its label the same in both states: the label says what the setting is, and the switch shows whether it's on.

<ComponentExample
  name="switch/basic"
  caption="Click Airplane mode, or focus the switch and press Space, to turn it on and off."
/>

## Installation

```bash
npm install @ui-sdk/effect @ui-sdk/core
```

## Composition

`Switch` is one headless component. Its `view` gets these parts:

```text
Switch
├── parts.root
│   └── parts.thumb
└── parts.input
```

Apply the root to a button and put the thumb inside it. The `input` part is the hidden native checkbox that takes part in forms: put it beside the button. Wrap the switch and its text in a label. The thumb stays mounted and gets the switch's state, so CSS can slide it from one end to the other.

`switch` is a reserved word, so name the `view` closure's argument `parts`.

## Usage

Call it in your view and apply its parts:

```ts
import * as Html from "@effect/ui/html/Html"
import { Switch } from "@ui-sdk/effect/switch"
import * as Schema from "effect/Schema"

const Example = Html.component({
  name: "Example",
  model: Schema.Null,
  message: Schema.Never,
}).make({
  init: () => null,
  update: ($) => $.model,
  view: (h) =>
    Switch(h, {
      view: (parts) =>
        h.label.children(
          "Airplane mode",
          parts.root(h.button).children(parts.thumb(h.span)),
          parts.input(h.input)
        ),
    }),
})

export { Example }
```

## Controlled

Keep `checked` in your Model, pass it as a prop, and change it in `update` when `CheckedChange` arrives. A [controller](#controller) from `createSwitchController()` changes it from anywhere, like the Toggle button below: call it from a Command. See [State and Events](../state-and-events) for the shared pattern.

## Form

Pass `name` to include the switch in a native form, and render its `input` part. A switch that's on submits its `value`, which defaults to `"on"`; a switch that's off submits nothing. Reset returns it to `defaultChecked`. Pass `form` with a form's id to join it from elsewhere on the page.

## Saving on Toggle

To save a change before it shows, keep `checked` in your Model and leave it as it is when `CheckedChange` arrives. Run a Command that saves, and change the Model when its result arrives.

The example ignores changes while a save is running, and shows a spinner in the thumb. `aria-busy` tells assistive technology the switch is busy; `update` is what blocks another change.

## Styling

Style the switch and its thumb with `data-checked` and `data-unchecked`, and use `data-disabled`, `data-readonly` and `data-required` for the rest. In an invalid field, the switch also gets `data-invalid` and `aria-invalid`; the thumb doesn't. Slide the thumb with `translate` on `data-checked`, and reverse it under `dir="rtl"`.

Each part has a `data-slot`, such as `switch`, and its state attributes are listed under [Data Attributes](#data-attributes).

## Accessibility

The switch follows the [WAI-ARIA switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/). The root gives its button the `switch` role, and the `input` part is a hidden native checkbox that takes part in forms.

### Keyboard

| Key   | Does                                   |
| ----- | -------------------------------------- |
| Tab   | Moves to the next switch               |
| Space | Turns it on or off                     |
| Enter | Submits its form, and never toggles it |
