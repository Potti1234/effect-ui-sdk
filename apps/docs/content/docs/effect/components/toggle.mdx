Use a toggle for a button that stays on until you press it again, like starring a document or turning on Bold. Put several in a toggle group to share one value, as a text editor's formatting buttons or a view switcher do.

/>

## Installation

```bash
npm install @ui-sdk/effect @ui-sdk/core
```

## Composition

`Toggle` and `ToggleGroup` are headless components. A toggle's `view` gets these parts:

```text
Toggle
├── toggle.root
└── toggle.icon
```

And a group's:

```text
ToggleGroup
├── toggleGroup.group
└── toggleGroup.join
    ├── Toggle (group: toggleGroup.join)
    └── Toggle (group: toggleGroup.join)
```

Apply `root` to a native button: it reports its state with `aria-pressed`. `icon` is optional: it holds an icon and hides it from screen readers. In a group, give each toggle a `value` and pass the group's `join` as its `group` prop; the group's value lists the pressed ones.

## Usage

Call it in your view and apply its parts:

```ts
import * as Html from "@effect/ui/html/Html"
import { Toggle } from "@ui-sdk/effect/toggle"
import * as Schema from "effect/Schema"

const Example = Html.component({
  name: "Example",
  model: Schema.Null,
  message: Schema.Never,
}).make({
  init: () => null,
  update: ($) => $.model,
  view: (h) =>
    Toggle(h, {
      view: (toggle) =>
        toggle
          .root(h.button.attr("aria-label", "Star"))
          .children(toggle.icon(h.span.children(starIcon(h)))),
    }),
})

export { Example }
```

Keep the label the same in both states: screen readers announce whether the button is pressed. An icon-only toggle needs an `aria-label`, as above. Set `defaultPressed` to start pressed. The toggle always uses `type="button"`, so pressing it never submits a form.

## Build Your Own

`@ui-sdk/effect/toggle` comes with a ready-made Toggle and ToggleGroup. If you'd like to build your own, with your own names, start from the `toggle` and `toggleGroup` primitives in `@ui-sdk/core`:

```ts title="pin.ts"
import { toggle } from "@ui-sdk/core/toggle"
import { createParts } from "@ui-sdk/effect/primitive"

const Pin = createParts(toggle, {
  name: "Pin",
  tags: { root: "button", icon: "span" },
})

export { Pin }
```

Each part keeps the behavior, state and data attributes of its ready-made counterpart. See [Rendering](../rendering) and [Custom Parts](../custom-parts) for more.

## Group

Put toggles in a `ToggleGroup`, from the same `@ui-sdk/effect/toggle` entry, to share a value and arrow-key navigation. Give the group an accessible name, each toggle a `value`, and pass the group's `join` to each toggle as `group`. Set `multiple` to let several toggles stay pressed.

```ts
ToggleGroup(h, {
  props: { multiple: true },
  view: (group) =>
    group.group(h.div.attr("aria-label", "Text formatting")).children(
      ["bold", "italic"].map((value) =>
        Toggle(h, {
          key: value,
          props: { value, group: group.join },
          view: (toggle) => toggle.root(h.button).children(value),
        })
      )
    ),
})
```

<ComponentExample
  name="toggle/group"
  caption="Press Bold and Italic to keep both pressed. Left and Right move focus without changing either."
/>

The group owns which toggles are pressed, so a toggle's own `pressed` and `defaultPressed` don't apply inside it. Its value is always an array, in the toggles' document order.

## Single Selection

Without `multiple`, pressing a toggle unpresses the others. Pressing the pressed toggle again clears the selection, unless you set `deselectable` to `false`, as this alignment group does. `deselectable` doesn't choose an initial value for you, so pair it with `defaultValue`.

<ComponentExample
  name="toggle/group-single"
  caption="Press Align center to replace Align start, then press Align center again. One alignment always stays pressed."
/>

`mirror` on Align start and Align end flips their icons in right-to-left text: `toggle.icon(h.span, { mirror: true })`. Use [Radio](./radio) instead when the arrow keys should select an option as they move; a toggle group moves focus first and waits for a press.

## Icon and Label

Put an icon beside the label with `toggle.icon`. The icon is hidden from screen readers, so the text alone names the button.

```ts
toggle.root(h.button).children(toggle.icon(h.span.children(pinIcon(h))), "Pin")
```

## Disabled

Set `disabled` on a toggle or a group to prevent presses. A disabled toggle can still start pressed, and a disabled `<fieldset>` around it disables it too.

```ts
Toggle(h, {
  props: { disabled: true, defaultPressed: true },
  view: (toggle) => toggle.root(h.button).children("Pin"),
})
```

A disabled toggle on its own leaves the tab order. In a group, disabled toggles stay reachable with the arrow keys and report `aria-disabled`, but ignore presses.

```ts
Toggle(h, {
  key: "underline",
  props: { value: "underline", disabled: true, group: group.join },
  view: (toggle) => toggle.root(h.button).children("Underline"),
})
```

## Focusable When Disabled

Set `focusableWhenDisabled` to keep a disabled toggle focusable. It uses `aria-disabled` and still ignores presses. Use `aria-describedby` to explain why it's unavailable:

```ts
h.div.children(
  Toggle(h, {
    props: { disabled: true, focusableWhenDisabled: true },
    view: (toggle) =>
      toggle
        .root(h.button.attr("aria-describedby", "pin-hint"))
        .children("Pin"),
  }),
  h.p.attr("id", "pin-hint").children("Only owners can pin messages.")
)
```

## Controlled

Keep `pressed` in your Model, pass it as a prop, and change it in `update` when `PressedChange` arrives. To refuse a change, leave the Model as it is. A [controller](#toggle-controller) from `createToggleController()` presses the toggle from anywhere, such as a keyboard shortcut: call it from a Command. Create one controller per mounted toggle.

```ts
import * as Command from "@effect/ui/Command"
import * as Component from "@effect/ui/Component"
import * as UiSchema from "@effect/ui/UiSchema"
import * as Html from "@effect/ui/html/Html"
import { createToggleController, Toggle } from "@ui-sdk/effect/toggle"
import * as Effect from "effect/Effect"
import * as Schema from "effect/Schema"

const star = createToggleController()

const StarMessage = UiSchema.TaggedEnum({
  RequestedPressedChange: { pressed: Schema.Boolean },
  ClickedToggleStar: {},
})

const ToggleStar = Command.make("ToggleStar", { args: {} }, () =>
  Effect.sync(() => {
    star.toggle()
    return Component.noop
  })
)

const StarButton = Html.component({
  name: "StarButton",
  model: Schema.Struct({ starred: Schema.Boolean }),
  message: StarMessage,
}).make({
  init: () => ({ starred: false }),
  update: {
    RequestedPressedChange: ($, { pressed }) => $.evolve({ starred: pressed }),
    ClickedToggleStar: ($) => $.run(ToggleStar.make({})),
  },
  view: (h, model) =>
    h.div.children(
      Toggle(h, {
        props: { pressed: model.starred, controller: star },
        onEmit: (event) =>
          event._tag === "PressedChange"
            ? StarMessage.RequestedPressedChange({ pressed: event.value })
            : undefined,
        view: (toggle) =>
          toggle
            .root(h.button.attr("aria-label", "Star"))
            .children(toggle.icon(h.span.children(starIcon(h)))),
      }),
      h.button
        .key("toggle-star")
        .on("click", StarMessage.ClickedToggleStar())
        .children("Toggle Star")
    ),
})

export { StarButton }
```

The event carries the new state as `value`, and its `reason`, `"press"` or `"imperative"`.

## Controlled Group

Keep `value` in your Model and change it in `update` when the group's `ValueChange` arrives, to own the group's value or to show it somewhere else. A toggle's own `PressedChange` arrives before the group's. A [controller](#togglegroup-controller) from `createToggleGroupController()` changes the value from anywhere, from a Command: `setValue([])` clears it.

```ts
ToggleGroup(h, {
  props: { multiple: true, value: model.formats, controller: editor },
  onEmit: (event) =>
    event._tag === "ValueChange"
      ? FormattingMessage.RequestedValueChange({ value: event.value })
      : undefined,
  view: (group) =>
    group.group(h.div.attr("aria-label", "Text formatting")).children(
      Toggle(h, {
        key: "bold",
        props: { value: "bold", group: group.join },
        view: (toggle) => toggle.root(h.button).children("Bold"),
      }),
      Toggle(h, {
        key: "italic",
        props: { value: "italic", group: group.join },
        view: (toggle) => toggle.root(h.button).children("Italic"),
      })
    ),
})
```

See [State and Events](../state-and-events) for controlled state, refusing changes and debugging.

## Vertical

Set `orientation: "vertical"` to move with Up and Down instead of Left and Right. The group and its toggles get `data-orientation`.

```ts
ToggleGroup(h, {
  props: { orientation: "vertical" },
  view: (group) =>
    group.group(h.div.attr("aria-label", "Tool")).children(tools),
})
```

## Loop

Arrow keys wrap from the last toggle to the first. Set `loop` to `false` to stop at the ends.

```ts
ToggleGroup(h, {
  props: { multiple: true, loop: false },
  view: (group) =>
    group.group(h.div.attr("aria-label", "Text formatting")).children(formats),
})
```

## Toolbar

Inside a [Toolbar](./toolbar), a toggle or a toggle group joins the toolbar's tab stop and arrow keys: pass `toolbarScope(toolbar.join)` from `@ui-sdk/effect/toolbar` as its `toolbar` prop. Inside a toolbar group, pass whether that group is disabled too: `toolbarScope(toolbar.join, disabled)`. A toggle in a toggle group takes only the group's `join`.

## Forms

Toggles don't submit values. Use [Checkbox](./checkbox) for several form choices or [Radio](./radio) for one. If you keep a toggle group in a form, copy its value into hidden inputs yourself.

## Custom Rendering

Apply a part to any element's builder to render it as that element, and read a part's state from `toggle.state`: a toggle's has `pressed`, and a group's, from `toggleGroup.state`, has `value`, its pressed values. Keep the part on the element people press, so its `aria-pressed` and keyboard behavior stay connected. See [Rendering](../rendering) for the rendering contract.

## Styling

Style the pressed state with `data-pressed`, and use `data-disabled` for unavailable toggles. A toggle with an `icon` gets `data-has-icon`, and its group gets `data-has-icons` while any toggle has one, which helps align icon and text content. `data-orientation` tells a group's toggles which way it runs.

Each part has a `data-slot`, such as `toggle`, and its state attributes are listed under [Data Attributes](#data-attributes).

### Events

Each event carries plain data, for your messages and your tests. `ValueChange` never arrives on mount.

| Event           | On            | Carries                                                                                              |
| --------------- | ------------- | ---------------------------------------------------------------------------------------------------- |
| `PressedChange` | `Toggle`      | `{ value, reason, source }`: the new state, and the [reason](#reasons). In a group, it arrives first |
| `ValueChange`   | `ToggleGroup` | `{ value, reason, source }`: the pressed toggles' values, and the [reason](#reasons)                 |

## Accessibility

A toggle follows the toggle button in the [WAI-ARIA button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/): a native button with `aria-pressed`. A group follows the keyboard of the [WAI-ARIA toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/), with one tab stop and arrow keys between toggles. It has the `group` role, not `toolbar`, so it can sit inside a [Toolbar](./toolbar), and not `radiogroup`, since its toggles are buttons.

### Keyboard

A group is one tab stop. Tab first enters on its first enabled pressed toggle, or its first enabled toggle, and later returns to the last focused one.

| Key          | Does                                                    |
| ------------ | ------------------------------------------------------- |
| Enter, Space | Presses or unpresses the focused toggle                 |
| Tab          | Moves into or out of a group                            |
| Left, Right  | Move focus in a horizontal group, swapped right to left |
| Up, Down     | Move focus in a vertical group                          |
| Home, End    | Move focus to the first or last toggle                  |
